# overlay/ — слой кастомизации форка

Все изменения этого форка живут **здесь**, в изоляции от upstream-кода
(`apps/`, `packages/`, `apiserver/` и т.д. трогаем по минимуму — только точки подключения).

**Зачем:** сохранить чистую синхронизацию с upstream (`makeplane/plane`). Чем меньше
мы меняем upstream-файлы, тем проще `git merge upstream/preview` и тем легче
перенимать фичи из других форков (`eyriehq/plane-plus`, `shbvn/plane`).

## Структура
- `features/` — изолированные модули фич (свои и перенятые из форков):
  - `pwa/` — Progressive Web App: manifest, service worker, иконки (Фаза 2, MVP мобильного)
  - `api-key-auth/` — API-key аутентификация `/api/v1` + `X-Api-Key` (порт из eyriehq, Фаза 3)
  - `epics/` — first-class эпики (порт из eyriehq, Фаза 3)
  - `time-tracking/` — учёт времени по задачам (порт/переписать из shbvn, Фаза 3)
  - `mobile-auth/` — `/m/auth` для нативного приложения (Фаза 4)
- `docs/` — внутренняя документация форка
- `ci/` — вспомогательные скрипты сборки (основные workflow — в `.github/workflows/`)

## Правила
1. Новый код — в `overlay/features/<name>/`.
2. Точки подключения внутри upstream-файлов помечать комментарием `// OVERLAY: <feature>`
   (чтобы их было видно при разрешении merge-конфликтов).
3. Каждая фича — отдельный PR в `develop` + smoke-тест.
4. Перед переносом из чужого форка — оценить (нужна ли, насколько изолирована, как портировать).
   Процедура — в [`../SYNC.md`](../SYNC.md).
